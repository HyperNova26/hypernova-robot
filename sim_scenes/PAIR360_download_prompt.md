# 작업: PAIR360 데이터를 기준 폴더 구조 그대로 NAS에서 내려받기

너는 이 컴퓨터에서 `HyperNova26/hypernova-robot` 레포를 다루는 코딩 에이전트다. 목표는 PAIR360 데이터셋 중 **기준 폴더(`data/Pair360_data`)에 있는 파일만, 같은 상대 경로·같은 파일명으로** NAS에서 내려받는 것이다. 데이터셋 전체를 받는 작업이 아니다.

## 0. 시작하기 전에 먼저 물어볼 것 (답을 받기 전에는 아무것도 받지 말 것)

한 번에 묶어서 물어본다.

1. 이 컴퓨터에서 `hypernova-robot` 레포의 경로는? (예: `~/ws/hypernova-robot`)
2. 기준 구조를 어디서 가져올까?
   - (a) 이 컴퓨터에 이미 받아 둔 `data/Pair360_data`가 있다 → 그 경로
   - (b) 다른 사람이 만든 목록 파일이 있다 → 파일 경로 또는 붙여넣기 (형식: `상대경로<TAB>바이트크기` 한 줄에 하나)
3. 받을 위치는? 기본값은 `<레포>/data/Pair360_data`.
4. 이미 있는 파일은 크기만 맞으면 건너뛸까, 아니면 전부 다시 받을까? 기본값은 크기 일치 시 건너뛰기.

(a)인데 받을 위치가 기준 폴더와 같다면, 이미 받은 상태일 수 있으니 "빠진 파일·크기가 틀린 파일만 채우는 작업"으로 이해했다고 말하고 진행한다.

## 1. 접속 정보

- 데이터셋 페이지: https://airlabkhu.github.io/PAIR-360-Dataset/ (Dataset 버튼)
- NAS 공유 링크(Synology): https://airlabdata.synology.me/sharing/tynrnpq4d
- 공유 비밀번호: `airlabairlab`

비밀번호는 환경변수 `PAIR360_PASSWORD`로만 넘긴다. 레포 안의 어떤 파일(스크립트, 설정, 로그, README)에도 적지 않는다. 로그·출력에도 찍지 않는다. 이 레포는 public이다.

## 2. 진행 순서

### 2-1. 기준 목록 만들기
- (a)라면 기준 폴더를 훑어서 `상대경로<TAB>크기` 목록을 만든다. 숨김 파일, 기준 폴더 안에서 사람이 따로 만든 파생물(`*_demo.bin` 같은 crop, 변환한 `.ply` 등)은 NAS에 없을 수 있으니 따로 표시만 해 둔다.
- (b)라면 받은 목록을 그대로 쓴다.
- 파일 수, 총 용량, 최상위 폴더 구조(2~3단계 트리)를 요약해서 보여준다.

### 2-2. NAS 쪽 구조 확인
- 공유 링크에 로그인해서 폴더를 재귀로 나열한다. 파일 다운로드는 아직 하지 않는다.
- Synology 공유 링크 API는 아래가 **추정**이다. 그대로 믿지 말고 실제 응답으로 확인한 뒤 써라.
  - 로그인: `POST /sharing/webapi/entry.cgi` — `api=SYNO.Core.Sharing.Login`, `method=login`, `version=1`, `sharing_id="tynrnpq4d"`, `password="..."` (문자열 값은 JSON 따옴표 포함). 응답 쿠키 `sharing_sid` 유지.
  - 목록: `POST /sharing/webapi/entry.cgi` — `api=SYNO.FolderSharing.List`, `method=list`, `version=2`, `folder_path="/..."`, `offset`, `limit`, `additional=["size","time"]`, `_sharing_id="tynrnpq4d"`.
  - 다운로드: `GET /fsdownload/webapi/file_download.cgi/<파일명>` — `api=SYNO.FolderSharing.Download`, `method=download`, `version=2`, `mode=download`, `stdhtml=false`, `dlink="<경로를 hex로 인코딩>"`, `_sharing_id="tynrnpq4d"`.
- 위 방식이 안 되면 추측으로 계속 바꿔 보지 말고, 브라우저 개발자 도구 Network 탭에서 로그인·폴더 열기·파일 하나 다운로드할 때의 요청을 "Copy as cURL"로 붙여 달라고 나에게 요청한다.

### 2-3. 기준 목록 ↔ NAS 경로 대응표
- 로컬 이름이 NAS 이름과 다를 수 있다. 레포 안에서도 `Traversal1/Parking_and_Open_theater/extra/T1_parking_Seq0.pcd`(frame.yaml)와 `T1_Parking_and_OpenTheater/extra`(README) 표기가 섞여 있다. **최종 저장 경로는 항상 기준 목록의 로컬 경로를 따른다.** 레포 도구가 그 경로를 기대한다.
- 파일마다 NAS 원본 경로를 짝지은 대응표를 만든다. 매칭 근거(같은 경로 / 같은 파일명+같은 크기 / 이름만 비슷함)를 적는다.
- NAS에는 압축 파일(zip/tar)만 있고 로컬은 풀린 상태라면, 어떤 압축을 받아 어디에 풀면 기준과 같아지는지 대응을 보여준다.
- 다음은 따로 묶어서 보여준다: NAS에서 못 찾은 기준 파일, 크기가 다른 파일, 후보가 여러 개인 파일. 이름만 비슷한 매칭이나 후보가 여러 개인 경우는 임의로 고르지 말고 나에게 확인받는다.

### 2-4. 받기 전 확인
- 받을 파일 수, 총 용량, 받을 위치의 남은 디스크 공간, 대략적인 시간을 보여주고 **내 승인을 받은 뒤** 시작한다. 남은 공간이 총 용량 + 10% 보다 적으면 시작하지 않는다.
- 먼저 작은 파일 하나를 받아 크기가 맞는지 확인한 뒤 본 작업으로 넘어간다.

### 2-5. 다운로드
- 다운로드 스크립트는 레포 밖(예: 받을 위치 옆 또는 임시 폴더)에 둔다. 레포 안에 남겨야겠다고 판단되면 위치와 이유를 보고서에 적는다. 어느 경우든 비밀번호는 넣지 않는다.
- 동작 요건:
  - 파일은 `<이름>.part`로 받고, 크기가 맞으면 최종 이름으로 바꾼다.
  - 서버가 Range를 지원하면 이어받기, 아니면 실패한 파일만 처음부터 다시 받는다.
  - 파일당 재시도 3회, 실패 목록을 남기고 나머지는 계속 진행.
  - 동시 다운로드는 2개 이하. NAS에 부담 주지 않는다.
  - 세션이 끊기면 재로그인 후 계속.
  - 진행 로그(파일명, 크기, 결과)는 받을 위치에 `_download_log.tsv`로 남긴다. 비밀번호·쿠키는 로그에 남기지 않는다.
- 압축 파일을 풀어야 하는 경우, 푼 결과가 기준 목록과 맞는지 확인한 뒤에만 압축 파일을 지울지 물어본다. 내 동의 없이 지우지 않는다.
- 기준 폴더나 기존 파일은 수정·삭제하지 않는다. 덮어쓰기는 0번 4번 답에 따른다.

### 2-6. 검증
- 받은 결과를 다시 훑어 기준 목록과 상대경로·크기를 대조한다. 일치 / 누락 / 크기 불일치 개수를 낸다.
- (a)이고 기준 폴더가 다른 위치라면, 작은 파일 몇 개는 SHA256도 비교한다. 큰 파일 전체 해시는 하지 않는다.
- `git -C <레포> status --porcelain`와 `git -C <레포> check-ignore -v data/Pair360_data`로 데이터가 git에 잡히지 않는지 확인한다. `.gitignore`에 `/data/`가 이미 있다.

## 3. 하지 말 것

- 커밋·푸시하지 않는다. git 변경이 생기면 그대로 두고 보고만 한다.
- 데이터셋 전체를 받지 않는다. 기준 목록에 없는 파일은 받지 않는다.
- 비밀번호를 파일·로그·출력에 남기지 않는다.
- 이름이 애매한 파일을 임의로 매칭하지 않는다.
- PAIR360은 ODbL 1.0이다. 데이터를 레포나 공개 위치에 올리지 않는다.

## 4. 끝나면 보고할 것

1. 기준 구조 요약(파일 수, 총 용량)과 실제로 받은 양
2. 경로 대응 방식 요약, 이름이 달랐던 파일 목록
3. 검증 결과: 일치 / 누락 / 크기 불일치 / 실패 개수와 해당 파일
4. 만든 파일(스크립트, 로그)의 위치, 레포 안에 생긴 변경이 있다면 그 목록
5. 내가 직접 확인해 볼 것: 예) `T1_parking_Seq0_demo.bin`, `T1-Parking_and_Peace_Amphitheater-0-lidar_pose.txt`처럼 레포 도구가 읽는 파일이 기대 경로에 있는지, CloudCompare로 대표 PCD 하나 열어 보기
