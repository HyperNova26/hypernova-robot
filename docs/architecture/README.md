# 아키텍처

시스템 아키텍처는 아직 없습니다. 이 디렉터리에는 구현 파일 목록이 아니라, 서브시스템을 어디서 끊고 그 경계에서 무엇을 주고받기로 했는지를 적습니다.

첫 초안은 최소한 이 정도는 다뤄야 합니다.

- 시스템 context와 외부 사용자·관제 시스템
- 기체, 구동기, 센서, 컴퓨팅, 전원의 경계
- 좌표계, 시간 동기화, 데이터 흐름과 명령 권한
- 안전 정지, 상태 감시, 장애 시 동작
- 실기와 시뮬레이션이 공유하는 인터페이스
- 설정, calibration, 로그, 버전을 식별하는 방식

## 기본 원칙

1. 팀 조직도가 아니라 시스템 경계로 모듈을 나눕니다.
2. 인터페이스와 단위, 좌표계, 시간 기준은 구현보다 먼저 정합니다.
3. 재사용 가능한 core 로직과 ROS 2·하드웨어 adapter를 분리합니다.
4. 안전은 기능 하나가 아니라 모든 계층이 지켜야 하는 조건입니다.

구체적인 선택은 [`docs/decisions/`](../decisions/)에 ADR로 남깁니다.
