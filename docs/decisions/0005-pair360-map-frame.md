# ADR-0005: PAIR360 mesh_v3 지형은 pair360_map 좌표를 변환 없이 쓴다

- 상태: **Proposed**
- 제안: 2026-11-19 (보행팀 작업 중 정함. 인식팀·공통팀과는 아직 합의하지 않았습니다)
- 대체: [ADR-0003](./0003-pair360-demo-frame.md)(기본 데모 지형에 한해)
- 관련: [PAIR360 mesh_v3 안내](../../sim_scenes/pair360_map_v3/README.md), S-005 localization 인터페이스([hn_interfaces 고정 토픽 목록](../../ros_pkgs/hn_interfaces/README.md)), M-002 팀 공통 원점

## 배경

[ADR-0003](./0003-pair360-demo-frame.md)은 S-004 데모 지형(2026-11-05 전달)을 시뮬레이터 world에 놓는 프레임을 정했습니다. 원시 좌표에서 원점을 옮기고 yaw를 −93.17° 돌린 ENU "데모 프레임"입니다. 경로 파일(`policies/urdf_v0/routes/pair360_demo.yaml`)과 재생 도구가 이 프레임을 씁니다.

2026-11-18에 지형 팀이 PAIR360 mesh_v3(MuJoCo용 hfield 장면)를 새로 전달했습니다. 이 자료는 다음과 같습니다.

- 좌표계가 `pair360_map`, 즉 PAIR360 T1 원시 XYZ(m, Z-up)입니다. README는 "팀 공통 원점(M-002)은 아직 적용 전"이라고 적었습니다.
- 지형 범위, 시작·목표·경유점이 모두 그 좌표입니다(시작 (−16.7, 123.4), 목표 (21.9, 184.4)).
- S-005 인터페이스의 `/localization/odometry`와 `/tf`도 `pair360_map` → `mlx_lidar`입니다.
- 새 지형은 S-004 데모 지형과 다른 지역입니다. 예전 경로 A는 이 지형 위에서 의미가 없습니다.

그래서 새 지형을 어느 좌표로 놓을지 정해야 합니다. 세 시뮬레이터, 경로 파일, 앞으로 올릴 Nav2의 `map` 프레임이 모두 이 선택에 걸립니다.

## 검토한 선택지

**A. `pair360_map` 좌표를 변환 없이 쓴다.** 지형 팀의 manifest 숫자를 그대로 쓰고, S-005의 대시보드·`/tf`와 같은 프레임이라 Nav2 `map`과 바로 맞습니다. 단점은 좌표 값이 큽니다(y가 약 120~190 m, 원점에서 멉니다). 큰 좌표에서의 부동소수점은 float32로도 약 1e-5 m 수준이라 문제가 되지 않았습니다(아래 결과).

**B. mesh_v3를 ADR-0003의 데모 프레임으로 변환한다.** 예전 경로 파일의 형식은 유지됩니다. 하지만 모든 곳에 변환이 끼고, 새 지형은 예전 지형과 다른 지역이라 예전 경로 숫자를 재사용할 수도 없습니다. S-005 토픽과도 프레임이 달라져 변환 노드가 하나 더 필요합니다.

**C. 지금 M-002 공통 원점을 가정해 변환한다.** M-002가 정해지지 않았는데 값을 지어내게 됩니다. 틀리면 모든 데이터를 다시 만들어야 합니다.

## 결정

A로 가고, 아래를 제안합니다. 합의 전까지는 `Proposed`입니다.

- 새 지형(`mesh_v3`)의 시뮬레이터 world 좌표는 `pair360_map` 값 그대로입니다. 평행이동·회전·수평화를 하지 않습니다.
- 세 시뮬레이터는 같은 hfield에서 만든 같은 지형을 같은 좌표에 놓습니다. 만드는 도구는 [`tools/map/hfield_scene_import.py`](../../tools/map/hfield_scene_import.py)입니다.
- 경로 파일(`sim_scenes/pair360_map_v3/routes.yaml`)도 `pair360_map` 좌표입니다. 도구가 manifest에서 만들고 손으로 고치지 않습니다.
- M-002가 정해지면 변환은 **한 곳**에서 합니다. 지형 팀 입력을 다시 받아 도구의 입력 좌표를 바꾸는 방식이 후보입니다.
- ADR-0003의 데모 프레임은 기본 지형에서 물러납니다. 예전 지형은 비교·회귀용으로 `MAP=demo`에서만 씁니다.

## 결과

- 새 지형의 세 시뮬레이터 좌표가 같고 변환 코드가 없습니다. 도구의 검증에서 쓴 메시와 MuJoCo hfield의 높이 차가 최대 3.0e-05 m였습니다.
- 경로 점검에서 지형 팀의 경로 길이(101.08 m)와 최대 경사(13.5%)가 독립적으로 같게 나왔습니다. 이는 좌표를 바꾸지 않았다는 근거이기도 합니다.
- ADR-0003은 `Superseded`입니다. 파일은 지우지 않았습니다. 예전 데모 지형(`MAP=demo`)과 그 경로 파일이 이 프레임을 쓰고, PR에서 링크되어 있기 때문입니다.
- 좌표가 M-002 전의 값이라, 공통 원점이 정해지면 한 번 바뀝니다. 그때까지 만든 경로·로그의 좌표는 `pair360_map`임을 기록해야 합니다(경로 파일이 이미 `frame:`을 적습니다).
- 인식팀이 같은 지도에 맞춰 두 번째 좌표계를 쓰고 있다면 이 결정과 어긋날 수 있습니다. 확인하지 못했습니다.

## 다시 볼 조건

- M-002 공통 원점이 정해질 때.
- 지형 팀이 새 mesh 버전을 전달해 좌표계가 바뀔 때.
- S-005 인터페이스의 map frame 이름이 바뀔 때.
- 인식팀·공통팀이 다른 좌표를 요구할 때. 합의하면 `Accepted`로 바꿉니다. 그 전에는 바꾸지 않습니다.
